# تصمیم‌های طراحی (چرا این‌طور ساخته شده)

از کامنت‌ها و ساختار کد استخراج شده؛ قبل از «سادی‌سازی» هر کدام این‌جا را بخوانید.

## دسترسی و داده
1. **دسترسی پروژه فقط از `project_memberships`** (و عضویت تیم هم لازم). «کتابخانه‌ی شخصی» عمداً حذف شد (migration 0005): `uploaded_by` فقط audit است. ← یک سند = یک scope (CHECK).
2. **ادمین همه‌جا دسترسی دارد** (شامل چت شخصی دیگران) — تصمیم آگاهانه سازمانی (CEO). پیاده‌سازی: `is_project_member` برای admin همیشه True.
3. **عضویت پروژه با join روی عضویت تیم** خوانده می‌شود تا عضویت قدیمی هیچ‌وقت از جایگاه تیمی بیشتر عمر نکند؛ علاوه بر آن حذف از تیم، عضویت پروژه‌ها را هم پاک می‌کند.
4. **فیلتر دسترسی داخل query برداری** (نه post-filter): chunk غیرمجاز هرگز از DB بیرون نمی‌آید و به LLM نمی‌رسد.
5. **ابزارها به آرگومان مدل اعتماد نمی‌کنند**: هر ابزار دوباره scope را از context می‌سازد؛ UUID حدس‌زده‌شده سند را باز نمی‌کند.
6. **linked_project_id فقط منبع RAG است، نه grant**؛ عضویت هر بار دوباره بررسی می‌شود.
7. **dedup فایل‌ها بر اساس hash** بدون نشت دسترسی: فایل فیزیکی مشترک، ولی ردیف `Document` و chunkها per-scope. بازاستفاده از chunk فقط با همان `embedding_model`.

## احراز هویت
8. **access کوتاه + refresh چرخشی**: access (JWT، ۳۰ دقیقه، stateless) برای هر درخواست؛ refresh مبهم و فقط-hash‌شده در DB، با claim اتمیک (`UPDATE … WHERE revoked_at IS NULL RETURNING`) تا یک‌بارمصرف باشد. SHA-256 (نه bcrypt) چون توکن خودش آنتروپی بالا دارد.
9. **اولین کاربر = super_admin** با advisory lock تا race نداشته باشد.
10. **نقش از DB در هر درخواست** (نه از JWT) تا تغییر نقش فوراً اثر کند.

## چت و agent
11. **Agent با tool-calling بومی** به‌جای pipeline ثابت retrieve→answer: مدل تصمیم می‌گیرد؛ ابزارها خطای خود را به متن تبدیل می‌کنند تا turn نمیرد؛ `MAX_STEPS=4` و حذف ابزارها در گام آخر برای تضمین پایان؛ dedup فراخوانی‌های یکسان.
12. **engine مستقل از transport** (callback): همان موتور هم SSE شخصی و هم WS گروهی را سرویس می‌دهد.
13. **ارسال گروهی از REST، دریافت از WS**: پیام قبل از پخش ذخیره شود؛ subscribe به Redis قبل از accept؛ catch-up با `(created_at, id)`. Redis pub/sub برای multi-instance.
14. **session جدا در کارهای detached** (SSE و پاسخ گروه): lifecycle وابستگی FastAPI با طول عمر stream سازگار نیست.
15. **artifact جدا از متن**: جدول و SQL دقیق از خروجی واقعی DB می‌آید، نه از نوشته‌ی مدل؛ مدل فقط خلاصه می‌نویسد و اعداد را نقل می‌کند. در SSE بلافاصله می‌آید تا حتی اگر خلاصه‌ی نهایی شکست خورد کاربر نتیجه را ببیند.
16. **تحمل قطع LLM**: retry شفاف قبل از اولین توکن؛ بعد از آن متن نیمه‌کاره + توضیح فارسی + artifact حفظ می‌شود.
17. **Providerها پشت ABC**: عوض کردن مدل/ارائه‌دهنده یا افزودن fallback بدون دست زدن به ingestion/retrieval.

## ingestion
18. **صف RQ و worker جدا** با replica قابل‌تنظیم؛ هر سند یک job (موازی‌سازی batch).
19. **متن بازسازی‌شده روی دیسک** (`.reconstructed.txt/json`) برای خواندن سریع صفحه‌ای توسط agent بدون query chunk.
20. **chunk به‌ازای صفحه** با شماره صفحه واقعی تا استنادها (`page`) دقیق باشد.
21. **OCR با LLM vision** (متن فارسی، جدول→Markdown، توضیح نمودار) به‌جای OCR کلاسیک؛ شکست OCR کل سند را خراب نمی‌کند.
22. **embedding با retry/backoff** در provider چون چند worker هم‌زمان rate limit می‌خورند.

## بازیابی اسناد
37. **hybrid داخل Postgres، نه Elasticsearch**: حجم کوچک، فیلتر دسترسی اتمیک با همان query، بدون سرویس/همگام‌سازی جدید؛ full-text (`simple` + نرمال‌سازی پایتون) برای عبارت‌های دقیق، trigram برای غلط املایی پرسش کوتاه، RRF برای ادغام بدون نرمال‌کردن امتیازها.
38. **یک تابع نرمال‌سازی** (`core/text_normalization.normalize`) هم برای ذخیره (`search_text`) و هم برای پرسش؛ اگر فرق کند match دقیق بی‌صدا خراب می‌شود. `search_text` در پایتون محاسبه می‌شود (نه تابع SQL) تا تست‌ها با `create_all` و backfill migration همان کد را اجرا کنند.
39. **`score` همان cosine می‌ماند** و `lexical_match` جدا است تا آستانه و UI عوض نشوند، و chunkی که واژگانی پیدا شده با cosine کم رد نشود.
40. **شرط حداقل دو کلمه‌ی متمایز** برای match واژگانی چون FTS در Postgres وزن IDF ندارد.
41. **لایه‌ی متنی PDF اعتماد‌پذیر نیست**: قبل از chunk/embedding هر صفحه ارزیابی می‌شود (`text_layer.py`)؛ صفحه‌ی با presentation forms برعکس یا نویز نمادی با OCR صفحه جایگزین می‌شود، و اصلاح قطعی فقط fallback است (اندازه‌گیری: خام ۰٪، اصلاح ~۷۰٪، OCR ~۹۴٪).
42. **re-rank با LLM اختیاری و fail-open**: بزرگ‌ترین جهش کیفیت بعد از اصلاح متن (hit@1 ۰٫۶۵→۰٫۸۵)، ولی هزینه/تأخیر دارد؛ پس پیش‌فرض خاموش و با هر خطایی به ترتیب قبلی برمی‌گردد.
43. **اندازه‌گیری قبل از تغییر**: chunk بزرگ‌تر، multi-query و dedupe آزموده و رد شدند (ارزشی نداشتند)؛ فقط مواردی که روی داده‌ی واقعی بهبود نشان دادند وارد شدند (`ops/retrieval-evaluation.md`).

## کانکتور حسابداری (Text-to-SQL ایمن)
23. **لایه‌ی `ai` به‌جای جدول‌های خام**: ۳۴۹۴ جدول/۳۶۳ view خام و join پیچیده‌ی تفصیلی؛ ۸۴ view با نام ثابت و توضیح فارسی. هر ستون یک معنی در همه‌ی view ها.
24. **دفاع چندلایه**: (الف) reader فقط `SELECT` روی schema `ai`؛ (ب) اعتبارسنج AST (یک SELECT، فقط ai، لیست کلمات ممنوع)؛ (ج) سقف ردیف (`SET ROWCOUNT`) و timeout؛ (د) DB در `READ_ONLY`؛ (ه) اتصال از شبکه‌ی internal.
25. **hybrid retrieval برای hint ها** (BM25 4-gram + بردار + RRF): واژه‌های دقیق کسب‌وکار («صورت وضعیت»، «حسن انجام کار») نباید فقط به embedding سپرده شوند؛ اگر embedding API خراب باشد سیستم هنوز کار می‌کند.
26. **حلقه‌ی تعمیر**: خطای validator/اجرا و حتی «صفر ردیف» به مدل برمی‌گردد؛ برای ۰ ردیف مقادیر واقعی ستون‌های فیلترشده کاوش و داده می‌شود (فیلترهای نام معمولاً به‌خاطر املا اشتباه‌اند نه نبودن داده). اولین `NO_SQL` یک‌بار challenge می‌شود چون اغلب تنبلی مدل است.
27. **مدل SQL جدا** (`LLM_SQL_MODEL`) از مدل چت.
28. **جمع/تعداد را سیستم حساب می‌کند**، نه مدل: چون مدل فقط ۶۰ ردیف می‌بیند؛ خروجی صریحاً می‌گوید «تعداد کل X است».
29. **OPTION(DISABLE_OPTIMIZER_ROWGOAL)** در هر query و trace flag 4138: بدون آن `TOP n … ORDER BY` روی view های fact گاهی ۶۰ثانیه می‌شد.
30. **refresh با DB جانبی و swap** تا DB زنده تا آخرین لحظه دست‌نخورده بماند و شکست قابل rollback باشد.
31. **همه‌ی مبالغ ریال**؛ نمایش تومان/میلیارد در formatter؛ سال مالی مهر→شهریور (`fiscal_year`)؛ «امروز» نسبت به `data_freshness` سنجیده می‌شود نه ساعت سیستم.
32. **لاگ کامل پرسش‌ها** (`db_query_logs`) برای بهبود مبتنی بر داده واقعی (few-shot و hint جدید) و feedback 👍/👎.
