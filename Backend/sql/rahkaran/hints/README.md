# هینت‌های Text-to-SQL برای لایه‌ی معنایی راهکاران (گام ۳)

مجموعه‌ی دانشی که Agent قبل از نوشتن SQL از آن بازیابی می‌کند. **هیچ کدی از بک‌اند در این گام عوض نشده**؛ خروجی یک فایل JSONL آماده‌ی embed است و گام ۴ (کانکتور) آن را می‌خواند.

## محتوا ([out/hints.jsonl](out/hints.jsonl))
| نوع | تعداد | منبع | کاربرد |
|---|---:|---|---|
| `view` | 90 | `ai.view_catalog` + `ai.column_catalog` + `VIEW_HINTS` در [notes.py](notes.py) | توضیح هر view، فیلترهای معمول، اشتباهات رایج، کلمات کلیدی فارسی و فهرست ستون‌ها (view های بزرگ در چند chunk) |
| `example` | 67 | [../examples/questions.py](../examples/questions.py) | سؤال فارسی → SQL تست‌شده (few-shot) |
| `glossary` | 40 | `ai.glossary` | اصطلاح کسب‌وکاری → view/ستون |
| `note` | 17 | `DOMAIN_NOTES` در notes.py | مفاهیم: سال مالی، تاریخ نسبی، وضعیت سند، واحد پول، علامت، قرارداد، هزینه‌ی قرارداد، حقوق، دارایی، بانک، نبودِ داده‌ها، سبک کوئری |
| پرامپت ثابت | 1 | [out/core_prompt.md](out/core_prompt.md) | قواعد همیشه‌فعال (۱۰ قاعده، حدود ۱۲۰۰ توکن) |

مجموع ~۱۳۲ هزار نویسه (حدود ۳۵ هزار توکن)؛ بزرگ‌ترین chunk حدود ۲.۶ هزار نویسه.

## روش بازیابی پیشنهادی برای گام ۴
1. **همیشه** `core_prompt.md` در system prompt.
2. embedding پرسش (BGE-M3 فعلی پروژه) + جستجوی ترکیبی (برداری + کلمات کلیدی/BM25) روی chunk ها؛ top-k ≈ 6–8: حداقل ۲ chunk از نوع `view`، تا ۲ `example`، تا ۲ `note/glossary`.
3. اگر chunk یک view در نتایج بود و ستون‌هایش چند بخش دارد، بخش‌های دیگر همان view را هم اضافه کن (id به شکل `view:<name>:<n>`).
4. بودجه‌ی توکن: core ≈ 1.2K + 6–8 chunk × ≈ 0.7K ≈ 6K توکن.
5. برای هر پرسش لاگ کن: متن، chunkهای بازیابی‌شده، SQL، موفقیت اجرا، تعداد ردیف، بازخورد کاربر — همین لاگ ماه اول مبنای بهبود (گام ۵) است.

## ارزیابی بازیابی (بدون API embedding، فقط واژگانی)
`python eval_retrieval.py [k]` پرسش را با BM25 (کلمه + n-gram نویسه) به chunk ها نگاشت می‌کند و می‌سنجد view های لازم در top-k هستند یا نه (کران پایین؛ embedding معمولاً بهتر است):

| مجموعه | k=4 | k=6 | k=8 |
|---|---:|---:|---:|
| ۶۷ سؤال نمونه، leave-one-out بدون نشت (همه‌ی view های لازم) | 88٪ (قبل از تنظیم دوم) | ۹۶٪ قبل از تنظیم کلیدواژه‌ها → ۹۹٪ بعد از آن | 97٪ |
| ۵۰ سؤال بازنویسی‌شده ([eval_set.py](eval_set.py)، حداقل یک view قابل‌قبول) | 100٪ | 100٪ | 100٪ |

⚠️ مجموعه‌ی ۵۰ تایی بعد از دیدن چند خطا کلمات کلیدی را تنظیم کرد، پس خوش‌بینانه است؛ عدد بی‌طرف‌تر ≈ ۹۶٪ (k=6) روی سؤال‌های نمونه قبل از تنظیم کلیدواژه‌هاست (۹۹٪ فعلی هم بعد از رفع دو خطای دیده‌شده است). بعد از جمع‌آوری سؤال‌های واقعی ماه اول مجموعه‌ی ارزیابی را با آن‌ها جایگزین کنید.

## اجرا
```bash
export RAHKARAN_AI_PASSWORD=...      # کاربر فقط‌خواندنی (sql/rahkaran/apply.py آن را می‌سازد)
python sql/rahkaran/hints/build_hints.py     # بازتولید out/ از دیتابیس + examples + notes
python sql/rahkaran/hints/eval_retrieval.py 6
```
بعد از هر تغییر در view ها/توضیحات (`descriptions.py`) یا `notes.py`/`questions.py` دوباره build کنید.

## چطور هینت اضافه کنیم
- view جدید: `VIEW_HINTS` در notes.py (کلمات کلیدی فارسی، کاربرد، فیلترها، اشتباهات) + توضیح در `descriptions.py`.
- مفهوم جدید یا دام جدید: `DOMAIN_NOTES`.
- سؤال واقعی کاربران (بعد از ماه اول): به `examples/questions.py` با SQL اصلاح‌شده و تست‌شده اضافه کنید؛ سؤال‌هایی که مدل غلط جواب داد ارزشمندترین نمونه‌ها هستند.
